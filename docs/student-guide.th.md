## ขั้น 1 — ลองของก่อน 10 นาที

```
/bot:demo
```

AI จะสร้างโปรเจคจากแม่แบบให้ (ถ้ายังไม่มี) แล้วรันบอทสามนาทีด้วย**ราคาจริงจากตลาด
แต่ออเดอร์เป็นกระดาษ** คำสั่งที่มันรันคือ

```bash
tradebot --dry-run --paper-live --config config/demo.yaml --iterations 36
```

กลยุทธ์ที่ใช้ชื่อ `ping_pong` — **เครื่องทดสอบระบบ ไม่ใช่กลยุทธ์ทำเงิน**
มันเข้าออกถี่เพื่อให้เห็นกลไก และระยะที่มันเล่นเล็กกว่าค่าธรรมเนียม
รันนานๆ จึง**ขาดทุนตามค่าธรรมเนียมแน่นอน** ห้ามเอาไปใช้กับเงินจริง

### สิ่งที่ต้องสังเกต

| เมื่อเห็น | แปลว่า |
|---|---|
| บรรทัดที่มีแต่ราคา | บอทดูแล้วไม่ทำอะไร — **นี่คือสถานะปกติของบอทที่ทำงานถูก** |
| `signal` | กลยุทธ์ขอเข้า บอกด้วยว่าราคาเท่าไร stop อยู่ตรงไหน |
| `order.qty` | ขนาดไม้ที่**ด่านความเสี่ยง**คิดให้ — ไม่ใช่ "ซื้อเท่าที่มีเงิน" |
| `receipt.simulated: true` | ได้ไม้แล้ว แต่เป็นกระดาษ |
| `exit.reason` | บอทปิดไม้เองเพราะอะไร |

### คำถามชวนคิด

- ทำไมบรรทัดส่วนใหญ่ถึง "ไม่ทำอะไร" และนั่นเป็นเรื่องดีหรือไม่ดี
- ขนาดไม้ `0.145` มาจากไหน (คำใบ้: ความเสี่ยงต่อไม้ ÷ (ระยะ stop + ค่าธรรมเนียมสองขาต่อหน่วย) — ดูใบงานข้อ 2)
- ไม้ที่ขาดทุน ขาดเพราะราคา หรือเพราะค่าธรรมเนียม

## ขั้น 2 — เปิดบอร์ด ดูโค้ดเดินทีละบรรทัด

บอร์ดคือกระดานที่โชว์ว่าบอท**กำลังทำอะไร** และ**เดินโค้ดบรรทัดไหน**อยู่

### เปิดยังไง

ใช้ได้สองแบบ เลือกแบบที่ผู้สอนเตรียมไว้ให้

**แบบ ก — ชุดพกพาที่ผู้สอนแจก** (ไม่ต้องลงอะไรเพิ่ม)

แตก `board-pack.zip` ไว้**ในโฟลเดอร์บอท** (โฟลเดอร์ที่มี `tradebot\` `config\` `logs\`)
ให้เป็น `<โฟลเดอร์บอท>\board-pack\` แล้วคลิกขวา `start.ps1` → Run with PowerShell
แล้วเปิด http://127.0.0.1:4340

> ถ้า Windows ไม่ยอมรันสคริปต์ ให้พิมพ์ใน PowerShell:
> `powershell -ExecutionPolicy Bypass -File .\start.ps1`

**แบบ ข — ในโปรเจคที่มีโฟลเดอร์ `board/`** (ต้องมี Rust และ trunk)

```powershell
cd board
.\start.ps1
```

> ⚠️ **อย่าใช้ `trunk serve`** แม้บางที่จะบอกให้ใช้ — มันเปิดหน้าเว็บได้แต่**ไม่ส่งข้อมูลบอท**
> บอร์ดจะว่างทั้งที่บอทรันอยู่ ต้องเปิดผ่าน `start.ps1` เสมอ

### ลิงก์ลัด — เปิดตรงไปที่จุดที่สอน

| ลิงก์ | เปิดที่ |
|---|---|
| http://127.0.0.1:4340/#bot | โซนบอท — การ์ดห้าขั้น |
| http://127.0.0.1:4340/#order | โซนบอท **เล่นซ้ำ tick ล่าสุดที่บอทส่งออเดอร์** |
| http://127.0.0.1:4340/#trip | ด่าน "ส่งคำสั่ง" คู่กับการ์ด **เส้นทางออเดอร์** — ตามออเดอร์จนจับคู่ |
| http://127.0.0.1:4340/#history | ประวัติการรันกับปฏิทิน |
| http://127.0.0.1:4340/#market | ตลาด |

### อ่านโซนบอทยังไง

การ์ดห้าใบเรียงตามที่การตัดสินใจหนึ่งครั้ง "เดินทาง" ผ่าน

```
1. ข้อมูลตลาด → 2. กลยุทธ์ → 3. ด่านความเสี่ยง → 4. ส่งคำสั่ง → 5. ไม้ที่ถืออยู่
```

- แต่ละใบโชว์**โค้ด Python จริง**ที่ขั้นนั้นใช้ ไม่ใช่คำอธิบาย
- **แถบส้มทึบ** คือบรรทัดที่กำลังทำงาน ณ ตอนนี้ของการเล่นซ้ำ มีหางจางๆ ตามหลัง
  ให้เห็นว่ากำลังเดินลง เดินจบแล้ววนกลับมาเริ่มใหม่จนกว่าจะมี tick ใหม่
- บรรทัด**จาง**คือบรรทัดที่รอบนี้ไม่ได้เดิน — กิ่งที่*ไม่ได้*ไปสำคัญพอๆ กับกิ่งที่ไป
- `×3` ท้ายบรรทัด = ลูปวนผ่านบรรทัดนั้นสามครั้ง
- การ์ดกว้าง **"โค้ดที่เพิ่งเดิน"** ข้างล่างโชว์ทั้งฟังก์ชัน กดเลข `1`–`5` เพื่อสลับขั้น
  กด `หยุด` เพื่อหยุดอ่านบรรทัดใดบรรทัดหนึ่ง

> สิ่งที่บอร์ดโชว์**ไม่ได้เดาเอา** บอทจดเองว่า interpreter เดินผ่านบรรทัดไหน
> ตามลำดับไหน (เก็บใน `logs/trace.jsonl` แยกจาก `logs/audit.jsonl`) บอร์ดแค่เอามาวาด

### ทำไมการ์ดบางใบเขียนว่า "รอบนี้ไม่ได้มาถึง"

tick ส่วนใหญ่บอทดูตลาดแล้ว**ไม่มีสัญญาณ** การตัดสินใจจึงหยุดที่ขั้น 2
ขั้น 3–4 ไม่ได้ทำงานเลย การ์ดก็บอกตรงๆ แบบนั้น — นี่คือบทเรียน ไม่ใช่ความผิดพลาด

**อยากเห็นรอบที่ส่งออเดอร์?** กด `ออเดอร์ล่าสุด` บนการ์ด "สิ่งที่บอทตัดสินใจ"
หรือกดรายการไหนก็ได้ในการ์ดนั้น การ์ดทั้งห้าจะเล่น tick นั้นซ้ำ
แถบบนขึ้นว่า **"กำลังเล่นซ้ำ tick 23:47:11"** กด `กลับไปล่าสุด` เพื่อกลับ

### ตามออเดอร์จนจับคู่ — การ์ด "เส้นทางออเดอร์"

"ส่งแล้ว" ยังไม่ใช่ "ได้ไม้" ระหว่างนั้นมีอีกหลายขั้น การ์ดนี้ (ขวาสุดของโซนบอท หรือเปิด `#trip`)
ตามออเดอร์ใบล่าสุดไปทีละขั้น

```
บอทตัดสินใจ → ส่งไปตลาด → เข้าสมุดคำสั่ง → รอจับคู่ → จบ
```

| ขั้น | บอกอะไร |
|---|---|
| ส่งไปตลาด | ออกไปกี่ ms หลังตัดสินใจ และ**ตลาดตอบกลับในกี่ ms** |
| เข้าสมุดคำสั่ง | ตลาดรับเข้าคิวตอนไหน |
| รอจับคู่ | ถ้ายังรอ จะ**นับวินาทีสด** พร้อมบอกว่าจับได้แล้วเท่าไรจากทั้งหมด |
| จบ | เต็มทั้งก้อนที่ราคาเฉลี่ยเท่าไร ใช้เวลารวมเท่าไร — หรือยกเลิก/ถูกปฏิเสธเพราะอะไร |

- **taker** = ราคาที่ตั้งชนคำสั่งที่รออยู่ในสมุดทันที ไม่ต้องรอ (ค่าธรรมเนียมแพงกว่า)
  **maker** = ไปรอในสมุดจนมีคนมาจับ
- ข้างล่างมีแถบเขียวว่าจับคู่แล้วกี่ % และรายการแต่ละไม้ที่จับ พร้อมเวลาหลังส่ง
- `‹ ›` ไล่ดูออเดอร์ก่อนหน้า · `ดูโค้ด tick นี้` เล่นซ้ำการ์ดห้าใบตอนที่ส่งใบนั้น
- เทรดกระดาษจะขึ้นว่า **"จำลอง"** เพราะไม่มีสมุดจริง ต้องรันบน testnet ถึงจะเห็นขั้น 3–4 ของจริง
- ถ้าเห็น "นาฬิกาเครื่องนี้ช้ากว่าตลาด ... หักออกแล้ว" แปลว่านาฬิกาคอมกับนาฬิกาตลาดไม่ตรงกัน
  บอร์ดคำนวณส่วนต่างแล้วหักให้ ตัวเลขเวลาที่เห็นจึงเป็นเวลาจริงของการเดินทาง

> ข้อมูลขั้น 3–5 มาจาก**บัญชีจริงบนตลาด** ต้องมีกุญแจ testnet ที่เซิร์ฟเวอร์ของบอร์ด
> (ไฟล์ `config/.env` เดียวกับที่บอทใช้) ไม่มีกุญแจ การ์ดจะตามได้ถึงแค่ "ตลาดตอบรับแล้ว"

### กลยุทธ์หน้าตาเป็นยังไง — การ์ด "หน้าตากลยุทธ์"

อยู่ใต้ด่าน "กลยุทธ์" วาดเฉพาะ tick ของรอบที่กำลังรัน (ping_pong):

- **เส้นขาว** = ราคา · **เส้นฟ้า** = เส้นกลาง (ค่าเฉลี่ย 12 ราคาล่าสุด)
- **แถบฟ้าจาง** = โซนที่กลยุทธ์ไม่ทำอะไร (ห่างเส้นกลาง ±0.03%)
- ราคาหลุด**ใต้แถบ** = ซื้อ (▲ เขียว) · ทะลุ**เหนือแถบ** = ขาย (▼ แดง)
- ถือไม้อยู่แล้ว ราคา**กลับมาแตะเส้นกลาง** = ปิด · หรือโดน stop (เส้นแดง) · หรือถือครบ 180 วิ
- วงกลมส้ม = กลยุทธ์อยากเข้า แต่ด่านความเสี่ยงไม่ให้
- บรรทัด **"ตอนนี้:"** บอกว่าราคาต้องขยับอีกกี่ % ถึงจะซื้อหรือขาย หรือถ้าถือไม้อยู่ ต้องรออะไรถึงจะปิด

ทุกเส้นมาจาก**กลยุทธ์บอกเอง** (เมธอด `chart()` ในคลาส) บอร์ดไม่ได้คำนวณเอง
กลยุทธ์ที่ไม่มี `chart()` จะเห็นแค่ราคากับจุดซื้อขาย

### เส้นออเดอร์บนกราฟแท่งเทียน (โซนตลาด)

- **เส้นประส้มกะพริบ** "รอจับคู่" = ออเดอร์ที่ยังค้างในสมุด
- **เส้นทึบเขียว/แดง** "ถือ ..." = ราคาเข้าของไม้ที่ถืออยู่ พร้อมกำไรขาดทุนที่ยังไม่ปิด
- **เส้นประแดง** "stop" = ราคาที่จะตัดขาดทุน
- **▲ / ▼** บนแท่ง = จุดที่ซื้อ / ขายจริง
- ไม่มีกุญแจ: เส้นมาจากบันทึกของบอท (ป้ายเขียนว่า "บันทึกของบอท") และจะไม่เห็นเส้นรอจับคู่

### โซนประวัติ

- **ประวัติการรัน** — ทุกรอบที่บอทเคยรัน ใหม่สุดบน กดรอบไหนจะพาไปเล่นซ้ำรอบนั้น
  รอบที่มีป้าย `เดาจาก audit` คือรอบที่เกิดก่อนบอทจะจดสมุดรอบการรัน
  บอร์ดเดาจากช่วงเงียบของเวลา
- **ปฏิทินรายวัน** — เขียว/แดงตามผลของวัน ช่องว่าง = วันที่บอทไม่ได้รัน (ไม่ใช่วันที่เท่าทุน)

### เรื่องเวลา

ทุกเวลาบนบอร์ดเป็น**เวลาไทย** (มุมขวาบนมีนาฬิกา) และ**วันของบอทก็เป็นวันไทย**
เพดานขาดทุนรายวันของบอท**รีเซ็ตตอนเที่ยงคืนเวลาไทย** ตรงกับวันบนปฏิทินของบอร์ด
การ์ด "ทุนกับสถานะบอท" เขียนว่า "กำไรขาดทุนวันนี้ (นับจากเที่ยงคืน)"
(ข้อมูลที่บอทเขียนลงไฟล์ยังเป็นเวลา UTC เหมือนเดิม แปลงเป็นเวลาไทยตอนแสดงเท่านั้น)

### คำถามชวนคิด

- เปิด `#order` แล้วไล่ดู: กลยุทธ์ตัดสินใจซื้อที่บรรทัดไหน ด่านความเสี่ยงคิดขนาดไม้ที่บรรทัดไหน
- tick ที่ "รอบนี้ไม่ได้มาถึง" ขั้น 3 — หยุดที่บรรทัดไหนของขั้น 2
- ถ้าลบด่านความเสี่ยงออก อะไรจะเกิดกับขนาดไม้
- (หลังขั้น 6) ออเดอร์ของคุณใช้เวลากี่ ms ตั้งแต่ส่งจนจับคู่ เป็น taker หรือ maker แล้วทำไม

## ขั้น 3 — สร้างบอทของตัวเอง (ยังไม่ต้องมีกุญแจ)

ทำเรียงลำดับ แต่ละคำสั่งได้ไฟล์ YAML ที่อ่านเป็นภาษาคนได้ใน `bot/`

| คำสั่ง | ทำอะไร | ได้ไฟล์ |

| `/bot:profile` | สัมภาษณ์ทุน ความเสี่ยงที่รับไหว เวลาที่ดูจอได้ ตลาดที่สนใจ | `bot/profile.yaml` |

## ขั้น 4 — ต่อ GRVT testnet

```
/bot:connect
```

AI จะถามก่อนว่าจะใช้ตลาดไหน (**ห้ามเดาว่าเป็น Binance**) แล้วพาขอกุญแจ testnet

### ขั้นที่คุณต้องทำเอง

1. เปิด https://testnet.grvt.io เชื่อม wallet — เป็นบัญชี testnet เงินในนั้นเป็นเงินปลอม
2. รับเงินทดลองจาก faucet ในหน้าเว็บ
3. เมนูโปรไฟล์ → API → สร้าง API key ใหม่
   **เปิดสิทธิ์เทรดอย่างเดียว ปิดสิทธิ์ถอนเงินเสมอ**
4. จะได้สามอย่าง: API key · private key (**แสดงครั้งเดียว**) · trading account id

### เก็บกุญแจที่ไหน

เปิดไฟล์ `config/.env` **ในเอดิเตอร์** แล้ววางเองกับมือ

```
GRVT_API_KEY=...
GRVT_PRIVATE_KEY=...
GRVT_TRADING_ACCOUNT_ID=...
```

> 🔒 **ห้ามพิมพ์กุญแจลงในแชทกับ AI** ถ้าเผลอวางไปแล้ว ให้ไปยกเลิกคีย์นั้นที่หน้าเว็บแล้วออกใหม่
> ไฟล์ `.env` อยู่ใน `.gitignore` แล้ว จะไม่ถูก commit

### ตรวจว่าต่อได้จริง โดยยังไม่ส่งออเดอร์

```bash
tradebot --doctor --config config/testnet.yaml
```

ถ้าขึ้นยอดเงินของบัญชี testnet ได้ แปลว่าใช้ได้

> มีกุญแจแล้ว บอร์ดจะโชว์**บัญชีจริงจากตลาด**ได้ด้วย (โซน "บัญชีจริง")
> กุญแจอยู่ที่เซิร์ฟเวอร์ของบอร์ดเท่านั้น เบราว์เซอร์ไม่เคยเห็นกุญแจ
> และเซิร์ฟเวอร์ของบอร์ด**ส่งออเดอร์ไม่ได้โดยโครงสร้าง**

## ขั้น 5 — สร้างโค้ด ทดสอบย้อนหลัง เทรดกระดาษ

| คำสั่ง | ทำอะไร |
|---|---|
| `/bot:scaffold` | สร้างไฟล์กลยุทธ์ของคุณใน `tradebot/strategies/` จากสเปค พร้อมเทส |
| `/bot:backtest` | ทดสอบย้อนหลังกับแท่งเทียนจริง + ตรวจ overfitting |
| `/bot:paper` | เทรดกระดาษกับราคาจริง + เกณฑ์จบการศึกษา 10 ข้อ |

> ผลทดสอบย้อนหลังที่ดี**ไม่ใช่**หลักฐานว่ากลยุทธ์ทำเงิน — การ์ด "อ่านก่อนเชื่อผลนี้"
> บนบอร์ด (โซนทดสอบ) บอกว่าต้องระวังอะไรบ้าง โดยเฉพาะถ้าจำนวนไม้น้อยกว่า 30

### ด่านตรวจ — ต้องผ่านก่อนขึ้น testnet ทุกครั้ง

```bash
tradebot --config config/testnet.yaml --check --strategy <ชื่อกลยุทธ์>
```

เครื่องเป็นคนตัดสิน ไม่ใช่คุณ ไม่ใช่ AI ตรวจ 4 ชั้น:

| ชั้น | ถามว่า |
|---|---|
| 1 สัญญา | ป้อนราคาทดสอบ 12 แบบ: ไม่พัง · ไม่ต่อเน็ตหรืออ่านไฟล์ · stop อยู่ฝั่งขาดทุน · ใช้เวลา `market.now` · **ราคาทะลุ stop แล้วขอปิดไม้** · ป้อนเดิมได้ผลเดิม |
| 2 เทสของคุณ | เทสใน `tests/` ที่พูดถึงกลยุทธ์นี้ผ่านหมด — ไม่มีเทสเลย = ไม่ผ่าน |
| 3 ย้อนหลัง | แท่งเทียนจริงที่เก็บไว้: ยิงสัญญาณไหม ถูกด่านความเสี่ยงปัดตกหมดไหม เพราะอะไร |
| 4 กระดาษ | บอทจริงกับตลาดจำลอง 30 tick ไม่มี error |

ท้ายรายงานบอก **PASS** หรือ **NOT YET** พร้อมข้อที่ตก แล้วเขียนผลไว้ที่ `logs/check-<ชื่อ>.json`
ลายนิ้วมือ (fingerprint) ในรายงานผูกกับเนื้อไฟล์กลยุทธ์ **แก้ไฟล์ตัวเดียวก็ต้องตรวจใหม่**

**ตัวบอทบังคับเอง** ทุกครั้งที่รันด้วย `--live` บอทอ่านรายงานนี้ก่อนต่อตลาด ถ้ายังไม่เคยผ่าน
หรือแก้ไฟล์หลังผ่าน หรือผ่านมาบนเหรียญ/timeframe อื่น บอทจะไม่ส่งอะไรเลย แล้วบอกคำสั่ง `--check`
ที่ต้องรันก่อน ไม่มีสวิตช์ให้ข้าม (ส่วน `--live --doctor` `--live --fetch-candles` `--live --resume`
ไม่ถูกกัน เพราะไม่ได้ให้กลยุทธ์ตัดสินอะไร)

ผ่านแปลว่า "ทำตามที่ออกแบบ ไม่พัง ไม่ยิงอะไรแปลกๆ" — **ไม่ได้แปลว่าทำกำไร**

> ข้อ "ราคาทะลุ stop แล้วขอปิดไม้" สำคัญที่สุด: ลูปตอนรันจริงไม่ตัด stop ให้ มันรู้แค่ราคาล่าสุด
> ถ้า `get_exit()` ไม่เช็ก stop เอง ไม้จะค้างเลย stop ไปเรื่อยๆ (ด่านนี้จับ ma_cross กับ random
> ที่มากับแม่แบบได้ตั้งแต่วันแรกที่ทำ แก้แล้ว)

## ขั้น 6 — รันบน testnet จริงสั้นๆ แล้วดูบนบอร์ด

```bash
tradebot --live --config config/testnet.yaml --iterations 24 --close-at-end
```

| ส่วนของคำสั่ง | ทำไมต้องมี |
|---|---|
| `--live` | testnet ก็ต้องสั่งชัดๆ ว่าจะส่งออเดอร์จริง ไม่งั้นบอทจะใช้กระดาษ |
| `--iterations 24` | วน 24 รอบแล้วหยุด (รอบละ 5 วินาที ≈ 2 นาที) |
| `--close-at-end` | **ปิดไม้ที่ค้างอยู่ก่อนจบ** รอบสาธิตจะได้ไม่ทิ้งไม้ไว้ข้ามคืน |

ระหว่างรัน เปิดบอร์ดไว้อีกหน้าต่าง แล้วดู

- การ์ดห้าใบเปลี่ยนตาม tick ใหม่ทุก 5 วินาที แถบส้มเริ่มเดินใหม่ทุกครั้ง
- พอบอทส่งออเดอร์ เส้นเชื่อมระหว่างการ์ดจะมีจุดวิ่งครบทุกเส้น
- โซน "บัญชีจริง" โชว์ยอดเงิน ไม้ที่ถือ และการ์ด "ประวัติบัญชี" ที่มีแท็บ ออเดอร์ / เทรด / ไม้ที่ปิด
  คอลัมน์เดียวกับหน้า Order History / Trade History / Position History ของ GRVT — วางเทียบกันได้ทีละแถว

จบแล้วดูที่**ประวัติการรัน** — รอบนี้จะขึ้นเป็นบรรทัดบนสุด พร้อมจำนวนไม้และผล

### คำถามชวนคิด

- ทุนที่บอทจดไว้ กับทุนจริงที่ตลาด ตรงกันไหม ถ้าไม่ตรง ต่างกันเพราะอะไร
- ค่าธรรมเนียมที่จ่ายไปจริง คิดเป็นกี่ % ของผลขาดทุน (ในการ์ด "ไม้ที่ปิดแล้ว")

## ปัญหาที่เจอบ่อย

| อาการ | สาเหตุ | แก้ |
|---|---|---|
| บอร์ดเปิดได้ แต่การ์ดบอทว่างหมด | เปิดด้วย `trunk serve` หรือเซิร์ฟเวอร์ชี้ `logs` ผิดที่ | ปิด แล้วเปิดใหม่ด้วย `start.ps1` |
| การ์ดเขียน "บอทยังไม่ได้จด" | บอทที่รันอยู่เป็นรุ่นเก่าที่ยังไม่จด trace | ปิดบอท แล้วรันใหม่ |
| การ์ดเขียน "เดามาจากคอนฟิก อาจไม่ใช่กลยุทธ์ตัวจริง" | บอทยังไม่เคยรันในโฟลเดอร์นี้ บอร์ดเลยอ่านจากคอนฟิกแทน | รันบอทหนึ่งรอบ บอร์ดจะรู้เองว่าใช้ไฟล์ไหน |
| การ์ดเขียน "รอบนี้ไม่ได้มาถึง" | tick นั้นไม่มีสัญญาณ เลยไม่ไปถึงขั้นนั้น | ปกติ — กด `ออเดอร์ล่าสุด` เพื่อดูรอบที่ไปถึง |
| บอทรันได้ ไม่ error แต่ไม่มีไม้เข้าเลย | ขนาดไม้ต่ำกว่าขั้นต่ำของตลาด (BTC testnet ขั้นต่ำ 100 USDT) | ดู `reject` ใน audit · `/bot:explain` ด้วยรหัสนั้น |
| `--doctor` บอกว่าต่อไม่ได้ | กุญแจผิด หรือเป็นกุญแจ prod | ออกกุญแจ testnet ใหม่ที่ testnet.grvt.io |
| เหมือนค้าง ไม่มีอะไรขึ้น | บอทหลับรอ `loop_interval` วินาทีระหว่างรอบ | รอ · หรือ `Ctrl+C` หยุดได้สะอาดเสมอ |
| เวลาบนบอร์ดไม่ตรงกับนาฬิกา | — | บอร์ดใช้เวลาไทย ดูนาฬิกามุมขวาบนเทียบ |
| ไม้ค้างหลังรันจบ | ลืมใส่ `--close-at-end` | `tradebot --close --yes --live --config config/testnet.yaml` |
