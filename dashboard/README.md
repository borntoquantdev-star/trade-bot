# Dashboard — ดูบอททำงานแบบ realtime

**แคนวาสที่ลากและซูมได้ มีสองแท็บ**

- **live** — บอทกำลังทำอะไรอยู่: ข้อมูลตลาดที่มันเห็น สัญญาณที่กลยุทธ์ออก
  ด่านความเสี่ยงอนุมัติหรือปฏิเสธ และออเดอร์ที่ส่งไป อัปเดตทันทีที่บอทตัดสินใจรอบใหม่
- **backtest** — ผลการทดสอบย้อนหลัง: เส้นทุน ผลเทียบกับการซื้อถือเฉยๆ
  สิ่งที่ด่านความเสี่ยงปฏิเสธ และไม้ทุกไม้ที่ปิดไป

ทั้งสองอยู่บนแคนวาสเดียวกัน แต่จำผังการ์ดกับตำแหน่งกล้องแยกกัน สลับด้วยแท็บบนแถบบน หรือกด `1` / `2`

การ์ดลากย้ายได้ ตำแหน่งจำไว้ในเบราว์เซอร์ · ลากพื้นที่ว่างเพื่อเลื่อน ล้อเมาส์เพื่อซูม
· มีมินิแมปกับแถบซูมมุมขวาล่าง และกรอบ group ล้อมสายโซ่หลักไว้

```bash
tradebot --dry-run --paper-walk --iterations 60     # หน้าต่างที่ 1: บอท
node dashboard/server.js --open                     # หน้าต่างที่ 2: dashboard
```

แล้วเปิด http://127.0.0.1:4317

แท็บ backtest ต้องมี `logs/backtest.json` ก่อน ซึ่งมาจาก `tradebot --backtest`
(ดู [docs/backtest.md](../docs/backtest.md)) ถ้าเก็บไว้ที่อื่นให้ชี้ด้วย `--backtest-file`

## มันทำงานยังไง

```
tradebot  ──เขียน──>  logs/audit.jsonl   1 บรรทัด = 1 การตัดสินใจ
                      logs/state.json    ทุนต้นวัน จุดสูงสุด สถานะ halt
                      logs/backtest.json ผลการทดสอบย้อนหลังหนึ่งครั้ง
                            │
                            │  server.js เฝ้าไฟล์ (poll 500ms) อ่านเฉพาะส่วนที่เพิ่ม
                            ▼
                      SSE /api/stream   event: snapshot (live) / backtest (ทดสอบ)
                            │
                            ▼
                      หน้าเว็บวาด node graph + กราฟราคา + log
```

**dashboard ไม่แตะบอทเลย** มันอ่านไฟล์ฝ่ายเดียว ไม่ได้ต่อตลาด ไม่มีทางส่งคำสั่ง
ปิดหน้าเว็บหรือฆ่าเซิร์ฟเวอร์ไม่กระทบบอทที่กำลังรัน และถ้า dashboard พัง บอทก็ไม่รู้ด้วยซ้ำ
นี่คือเหตุผลที่แยกเป็นคนละโปรเซส ไม่ยัดเว็บเซิร์ฟเวอร์เข้าไปในลูปเทรด

## การใช้งานแคนวาส

| ทำอะไร | ยังไง |
|---|---|
| เลื่อนจอ | ลากพื้นที่ว่าง |
| ซูม | ล้อเมาส์ หรือปุ่ม − / + มุมขวาล่าง |
| พอดีจอ | ปุ่ม `Fit` หรือกด `F` |
| ย้ายการ์ด | ลากที่หัวการ์ด (ตำแหน่งถูกจำไว้) |
| คืนผังเดิม | ปุ่ม ⟲ ในแถบเครื่องมือซ้าย |
| ซ่อนเส้นต่อ | ปุ่ม ∿ หรือกด `W` |
| หยุดดูภาพนิ่ง | ปุ่ม ⏸ หรือกด `space` (บอทยังรันต่อ) |
| สลับแท็บ | กดที่แท็บบนแถบบน หรือกด `1` (live) / `2` (backtest) |

การ์ดบนแท็บ live: ห้าขั้นของสายโซ่ (อยู่ในกรอบ `PIPELINE`), กราฟราคา,
การ์ดบัญชี และ log การตัดสินใจ

การ์ดบนแท็บ backtest: ผลการทดสอบ, เทียบกับการไม่ทำอะไร, ความเสี่ยงที่ต้องทน,
คุณภาพของไม้, เส้นทุน, ไม้ที่ปิดแล้ว, สิ่งที่ด่านปฏิเสธ และข้อจำกัดที่ต้องอ่านก่อนเชื่อ

## ห้าขั้นที่เห็นบนหน้าจอ

| ขั้น | เป็น ready เมื่อ | เป็น blocked / error เมื่อ |
|---|---|---|
| ข้อมูลตลาด | อ่านราคาและทุนได้ | `broker read failed` |
| กลยุทธ์ | ออกสัญญาณในรอบนี้ | กลยุทธ์ throw |
| ด่านความเสี่ยง | อนุมัติเป็น `SizedOrder` | ปฏิเสธ (โชว์ reject code เป็นภาษาไทย) หรือบอท halt |
| ส่งคำสั่ง | ตลาดรับออเดอร์แล้ว | broker ปฏิเสธ · เป็นสีฟ้าประถ้าเป็น paper |
| ไม้ที่ถืออยู่ | มี position เปิดอยู่ | — |

สีขอบการ์ด: เทา = รอ · เหลือง = กำลังทำ · เขียว = พร้อม · แดง = ถูกปฏิเสธ · ฟ้าประ = จำลอง

## ตัวเลือก

```bash
node dashboard/server.js --help
  --port <n>     ค่าตั้งต้น 4317
  --host <ip>    ค่าตั้งต้น 127.0.0.1 (เปิดเฉพาะในเครื่องนี้)
  --logs <dir>   โฟลเดอร์ log ของบอท (ค่าตั้งต้น ../logs)
  --backtest-file <f>  ผลการทดสอบย้อนหลัง (ค่าตั้งต้น <logs>/backtest.json)
  --poll <ms>    ความถี่ตรวจไฟล์ (ค่าตั้งต้น 500)
  --open         เปิดเบราว์เซอร์ให้
```

ถ้าบอทเขียน log ไว้ที่อื่น (`--audit-file` / `--state-file`) ให้ชี้ `--logs` ไปโฟลเดอร์นั้น

`--host 0.0.0.0` ทำได้แต่**ไม่ควร**: หน้านี้เปิดสถานะพอร์ตและยอดเงินของคุณ และไม่มีการล็อกอิน

## API

| route | ได้อะไร |
|---|---|
| `GET /api/stream` | SSE · ส่ง `snapshot` กับ `backtest` ทุกครั้งที่ไฟล์เปลี่ยน |
| `GET /api/snapshot` | JSON ภาพปัจจุบันของบอท |
| `GET /api/backtest` | JSON ผลการทดสอบย้อนหลัง (ย่อจุดเส้นทุนแล้ว) |

รูปร่างของทั้งสองมาจาก `derive()` ใน `lib/pipeline.js` กับ `lib/backtest.js`
ทั้งคู่เป็น pure function และถูกโหลดจากไฟล์เดียวกันทั้งฝั่งเซิร์ฟเวอร์และฝั่งเบราว์เซอร์
จึงไม่มีทางคิดไม่ตรงกัน

เส้นทุนถูก**ย่อก่อนออกจากเซิร์ฟเวอร์** เพราะการทดสอบหนึ่งปีบน 5m คือ 115,199 จุด
ไฟล์ 11 MB — ย่อโดยเก็บจุดต่ำสุดกับสูงสุดของทุกช่วงไว้ เหลือไม่กี่ร้อยจุด
ถ้าสุ่มเก็บทุกจุดที่ n หลุม drawdown กลางทางจะหาย แล้วกราฟจะโกหกในทางที่สวยขึ้น

## เทส

```bash
cd dashboard && npm test        # 70 เทส ไม่ต้องต่อเน็ต ไม่ต้องมีบอทรันอยู่
```

ครอบ: การอ่านไฟล์แบบต่อท้าย (บรรทัดที่ยังเขียนไม่จบ, ไฟล์ถูกเริ่มใหม่, JSON เสีย),
การแปลงเป็น node graph ทุกสถานะ, คำแปล reject code ทั้ง 13 ตัว,
การอ่านผล backtest (สตริงเป็นตัวเลข, null ไม่กลายเป็นศูนย์, การย่อเส้นทุนโดยไม่กิน drawdown),
และเทสจริงที่เปิดเซิร์ฟเวอร์ ต่อ SSE แล้วเขียนไฟล์ใหม่เพื่อดูว่ามันถึงหน้าเว็บ

## ที่มาของหน้าตา

**กลไก** ถอดแบบมาจาก [Trade Bot Designer](../docs/dashboard.md): กล้อง
`(x, y, scale)` ที่ใส่เป็น transform เดียวบน layer, การ์ดวางด้วย absolute position
พร้อมหัวการ์ด, กรอบ group ที่มีป้ายชื่อ, เส้นต่อ SVG เส้นประ, มินิแมปกับแถบซูม
ของเดิมเป็นการจำลองล้วน ของนี้อ่านจากบอทที่รันจริง

**หน้าตา** ทำตามบอร์ดของ [Symvibe](https://www.symvibe.com): พื้นดำอุ่นลายจุด
แถบต่างๆ ลอยเป็นเกาะมนแทนแถบทึบติดขอบจอ ขอบการ์ดบางระดับเส้นผม
และตัวเลข/เวลา/รหัส/คำสั่งเป็น monospace เสมอ

**ส้มแปลว่า "ระบบ" ไม่เคยแปลว่า "เงิน"** — แท็บที่เลือก เครื่องมือที่ถือ เส้นที่มีข้อมูลวิ่ง
ส่วนสถานะใช้เขียว/เหลือง/แดงคนละชุด ถ้าปนกันเมื่อไร สีที่แปลว่า "กำลังเลือกอยู่"
จะไปอยู่ข้างสีที่แปลว่า "ขาดทุน" ซึ่งเป็นความสับสนเดียวที่หน้าจอเทรดรับไม่ได้
ด้วยเหตุผลเดียวกัน กราฟราคาบนแท็บ live จึงเป็นสีครีมเฉยๆ เพราะราคาไม่ใช่กำไรขาดทุน

ไม่โหลดฟอนต์จากข้างนอก หน้านี้ผูกกับ 127.0.0.1 และต้องเปิดได้ตอนเน็ตหลุด

## ข้อจำกัด

- **แสดงอดีต ไม่ใช่อนาคต** ทุกอย่างบนหน้านี้คือสิ่งที่บอทบันทึกไว้แล้ว
- **ช้ากว่าบอทได้ถึง 500ms** ตามรอบ poll (ปรับด้วย `--poll` ได้แต่ไม่ช่วยอะไรมาก)
- **เก็บแค่ 2,000 บรรทัดล่าสุด** ในหน่วยความจำ ของเก่ากว่านั้นยังอยู่ในไฟล์แต่ไม่ขึ้นจอ
- **กราฟคือราคาที่บอทเห็นตอนตัดสินใจ** ไม่ใช่กราฟแท่งเทียนของตลาด
- **ไม่มีการล็อกอิน** เพราะผูกกับ 127.0.0.1 เท่านั้น
