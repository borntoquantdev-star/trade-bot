# Board — กระดานไร้ขอบเขตสำหรับเฝ้าบอท

แคนวาสที่ลากและซูมได้ไม่รู้จบ วางการ์ดได้ตามใจ เขียนด้วย **Rust** ทั้งก้อน
คอมไพล์เป็น **WebAssembly** แล้วเปิดในเบราว์เซอร์ — โค้ดชุดเดียวกันนี้
คอมไพล์เป็นแอปเดสก์ท็อปได้ด้วยโดยไม่ต้องเขียนใหม่

```
board/
  app/       บอร์ด (eframe/egui) → WASM สำหรับเบราว์เซอร์ + ไบนารีเดสก์ท็อป
  server/    Axum เสิร์ฟ WASM และอ่านไฟล์ที่บอทเขียน
  Dockerfile รวมทั้งสองอย่างเป็นอิมเมจเดียว
```

## เปิดบอร์ด — คำสั่งเดียว

```powershell
cd board
.\start.ps1
```

แล้วเปิด http://127.0.0.1:4340 ในเบราว์เซอร์

สคริปต์สร้างหน้าเว็บให้ถ้ายังไม่มี แล้วชี้ตัวแปรสี่ตัวให้ถูกที่ ซึ่งเป็นสี่ที่ที่จำยาก
และเป็นเหตุผลเดียวที่สคริปต์นี้มีอยู่:

| ตัวแปร | ชี้ไปที่ | พลาดแล้วเกิดอะไร |
|---|---|---|
| `BOARD_DIST` | `app\dist` | **trunk สร้างไว้ที่ `app\dist` แต่เซิร์ฟเวอร์หาที่ `dist`** เปิดมาได้ 404 เปล่าๆ |
| `BOARD_LOGS` | `..\logs` | การ์ดฝั่งบอทว่างหมด ทั้งที่บอทรันอยู่ |
| `BOARD_CANDLES` | `..\data\candles` | กราฟย้อนหลังไม่ขึ้น |
| `BOARD_ENV_FILE` | `..\config\.env` | การ์ดฝั่งบัญชีบอกว่ายังไม่ได้ตั้งกุญแจ (ที่เหลือยังดูได้) |

ไม่มีกุญแจก็เปิดได้ ข้อมูลตลาดทั้งหมดเป็นของสาธารณะ

> **ถ้าแก้ `start.ps1` แล้วมันพัง** ให้เช็คว่าไฟล์ยังเป็น UTF-8 **พร้อม BOM** อยู่ไหม
> Windows PowerShell 5.1 อ่าน `.ps1` ที่ไม่มี BOM เป็น ANSI ภาษาไทยในไฟล์จะกลายเป็นขยะ
> แล้วขึ้น `Unexpected token` ที่บรรทัดที่ไม่มีอะไรผิดเลย

หน้าต่างเดสก์ท็อปก็ได้ ไม่ต้องใช้ trunk และคอมไพล์เร็วกว่ามาก (ใช้ตอนไล่ UI):

```powershell
cargo run -p board --bin board-native
```

## รันด้วย Docker (แจกให้ทั้งห้อง)

```bash
docker build -t tradebot-board .          # ~4 นาที ได้อิมเมจ 91 MB
docker run -p 4340:4340 -v "$PWD/logs:/logs:ro" tradebot-board
```

แล้วเปิด http://127.0.0.1:4340

**บน Git Bash ของ Windows ต้องนำหน้าด้วย `MSYS_NO_PATHCONV=1`** ไม่งั้นมันจะแปลง
`/logs` เป็น `C:/Program Files/Git/logs` แล้วบอร์ดจะบอกว่าหาไฟล์ไม่เจอทั้งที่ mount แล้ว
(PowerShell กับ cmd ไม่มีปัญหานี้)

```bash
MSYS_NO_PATHCONV=1 docker run -p 4340:4340   -v "U:/path/to/grvt_demo_bot/logs:/logs:ro"   -v "U:/path/to/grvt_demo_bot/data/candles:/candles:ro"   -e BOARD_CANDLES=/candles tradebot-board
```

- `-v .../logs:/logs` คือโฟลเดอร์ที่บอทเขียน `audit.jsonl` / `state.json` / `backtest.json`
  **ไม่ต่อก็ได้** บอร์ดจะยังเปิดและแสดงราคาตลาดสดตามปกติ
- **ไม่ต้องใส่ API key ที่ไหนเลย** — ดูเหตุผลข้างล่าง

## รันตอนพัฒนา

```bash
# ในเบราว์เซอร์ พร้อม hot reload (แก้โค้ดแล้วหน้าเว็บอัปเดตเอง)
# ข้อแลกเปลี่ยน: trunk serve ไม่ได้เสิร์ฟ /api/* ให้ ต้องเปิด start.ps1 ไว้อีกหน้าต่าง
cd app && trunk serve --port 4341

# พิสูจน์ว่าต่อตลาดได้จริง ไม่ต้องเปิด UI
cargo run -p board --example probe
cargo run -p board --example probe -- prod ETH_USDT_Perp

# เทส
cargo test
```

## ทำไมบอร์ดไม่ต้องใช้ API key

GRVT มี stream **สาธารณะ** ที่ไม่ต้องยืนยันตัวตน บอร์ดต่อตรงจากเบราว์เซอร์

```
wss://market-data.testnet.grvt.io/ws        (prod: market-data.grvt.io)
{"request_id":1,"stream":"v1.mini.s","feed":["BTC_USDT_Perp@500"],
 "method":"subscribe","is_full":true}
```

ได้ mark/index/last price · best bid/ask พร้อมขนาด · funding · open interest
(`@500` คือจังหวะอัปเดตเป็นมิลลิวินาที)

ผลที่ตามมาสองข้อ และทั้งสองข้อสำคัญ:

1. **นักเรียนเปิดบอร์ดดูตลาดจริงได้ก่อนจะมีบัญชี** ไม่ต้องรอใครอนุมัติอะไร
2. **บอร์ดไม่เคยถือความลับที่ส่งออเดอร์ได้** ต่อให้มีคนเข้าถึงเครื่องที่รันบอร์ด
   ก็ไม่มีคีย์ให้ขโมย และไม่มีเส้นทางจากหน้าจอนี้ไปถึงการสั่งซื้อขาย
   — **ในโหมดปกติ** (`board-server`, Railway, `start.ps1`) ข้อนี้เป็นจริงทุกคำ
   ส่วน**โหมดแอป** (`TradeBot.exe` หรือ `BOARD_CONTROL=1` บน loopback) ต่างออกไปและถูกจำกัดไว้
   อ่าน[โหมดควบคุม](#โหมดควบคุม-และ-tradebotexe-ดับเบิลคลิกแล้วใช้ได้เลย)

## จัดการ์ดบนบอร์ด

**ไม่มีโหมด** บอร์ดทำงานเหมือนเดิมทุกอย่าง การคลุมเลือกอยู่ใต้ปุ่ม Shift เฉยๆ

| ทำแบบนี้ | ได้แบบนี้ |
|---|---|
| ลากที่ว่าง | เลื่อนบอร์ด **เหมือนเดิมทุกอย่าง** |
| **Shift + ลาก** ที่ว่าง | คลุมเลือกการ์ด ใบไหนโดนกรอบแตะก็ติดมา |
| ลาก **หัวการ์ด** ใบที่เลือกไว้ | ย้ายทั้งกลุ่มไปพร้อมกัน |
| คลิกที่ว่าง หรือกด **Esc** | ยกเลิกที่เลือกไว้ |
| ปุ่ม **จัดใหม่** บนแถบบน | คืนตำแหน่งการ์ดทุกใบเป็นค่าตั้งต้น |

เหตุผลที่ไม่ทำเป็นโหมด: โหมดคือสถานะที่คนต้องจำว่าตอนนี้อยู่ตรงไหน และเป็นสถานะที่ค้างได้
ปล่อยปุ่ม Shift เมื่อไหร่บอร์ดก็กลับเป็นบอร์ดเมื่อนั้น ไม่มีอะไรให้สลับกลับ

ส่วนกราฟที่ซูมอยู่ยังกินการลากของตัวเองเหมือนเดิม (ลากบนกราฟ = เลื่อนกราฟ ไม่ใช่เลื่อนบอร์ด)

**ตำแหน่งการ์ดถูกจำไว้** จัดเสร็จแล้วปิดเปิดใหม่ก็อยู่ที่เดิม
เก็บใน `localStorage` ของเบราว์เซอร์ หรือไฟล์ `board-layout.json` สำหรับหน้าต่างเดสก์ท็อป
(เปลี่ยนที่เก็บด้วย `BOARD_LAYOUT`) · เก็บแค่ **ตำแหน่ง ไม่เก็บขนาด**
เพราะการ์ดที่เวอร์ชันใหม่เพิ่มบรรทัดเข้าไปควรสูงตามที่เวอร์ชันใหม่วาด ไม่ใช่สูงตามของเก่า
· ไฟล์เสียหรือมาจากคนละเวอร์ชันก็ไม่พัง ใช้เท่าที่ใช้ได้ ที่เหลืออยู่ที่เดิม

## ฝั่งบัญชี — ต้องมีกุญแจ และกุญแจอยู่ที่เซิร์ฟเวอร์เท่านั้น

ยอดเงิน ไม้ที่ถือ ออเดอร์ และค่าธรรมเนียม เป็นข้อมูลของบัญชีใดบัญชีหนึ่ง
ต้องยืนยันตัวตนถึงจะขอได้ จึงอยู่ใน `server/src/account.rs` **ไม่ใช่ในเบราว์เซอร์**

กฎข้อเดียวที่กำหนดรูปร่างของทั้งไฟล์นั้น:

> เบราว์เซอร์ไม่เคยได้รับกุญแจ ไม่เคยได้รับคุกกี้ ไม่เคยได้รับเลขบัญชี
> มันถามเซิร์ฟเวอร์เป็นคำๆ แล้วได้ตัวเลขกลับไป

- **โค้ดของเซิร์ฟเวอร์เองไม่เคยสร้างออเดอร์** เส้นทางฝั่งบัญชีอ่านอย่างเดียวโดยโครงสร้าง
  รายชื่อที่ยิงได้มีเจ็ดชื่อและทุกชื่อเป็นคำถาม
  `create_order` `cancel_order` `transfer` ไปไม่ถึงไม่ว่าจะพิมพ์อะไรเข้ามา
  (บอร์ดที่ส่งออเดอร์ได้ คือบอร์ดที่วันหนึ่งจะส่งออเดอร์โดยไม่ได้ตั้งใจ)
  **ข้อยกเว้นเดียว:** ในโหมดแอป (`TradeBot.exe` / `BOARD_CONTROL=1` ผูก loopback เท่านั้น) เซิร์ฟเวอร์
  **สั่งเริ่ม/หยุดโปรเซสบอท**ได้ — เฉพาะ paper กับ testnet (คำสั่งที่รันตายตัวใน `control.rs`
  ใช้ `config/demo.yaml` กับ `config/testnet.yaml` เท่านั้น เบราว์เซอร์ใส่อาร์กิวเมนต์เองไม่ได้)
  ออเดอร์ทุกใบยังมาจากบอท ผ่าน `risk_gate()` ไม่ได้มาจากเซิร์ฟเวอร์
- **ใช้แค่ api key ไม่ต้องใช้ private key** GRVT แลกคุกกี้ให้จาก api key เฉยๆ
  สิ่งที่โปรเซสนี้ถืออยู่จึงย้ายเงินไม่ได้แม้จะหลุดออกไป
- **ไม่มีกุญแจไม่ใช่ error** การ์ดฝั่งบัญชีบอกว่ายังไม่ได้ตั้ง ส่วนข้อมูลตลาดทำงานตามปกติ

ตั้งกุญแจด้วย `GRVT_API_KEY` หรือวางไว้ในไฟล์ `.env`
ซึ่งเซิร์ฟเวอร์จะหาตามลำดับ `BOARD_ENV_FILE` → `./.env` → `../config/.env` → `config/.env`
(ไฟล์ `config/.env` ของบอทอยู่ในนั้นด้วย เพราะการให้คนเก็บความลับเดียวกันสองที่
แปลว่าวันหนึ่งจะมีที่หนึ่งเก่าค้างไว้)

```bash
cd board
BOARD_ENV_FILE=../config/.env BOARD_LOGS=../logs cargo run -p board-server
```

เลข `sub_account_id` ที่ใช้ถามไม่ต้องไปหาเอง: ถ้า `.env` ไม่ได้บอก
เซิร์ฟเวอร์ใช้เลขที่ตอบกลับมาตอนล็อกอินด้วย api key

## สิ่งที่บอร์ดอ่านจากบอท

`server/` อ่านไฟล์ที่บอท Python เขียนไว้อยู่แล้ว ไม่ต้องแก้ตัวบอท

| route | มาจาก |
|---|---|
| `GET /api/state` | `logs/state.json` |
| `GET /api/backtest` | `logs/backtest.json` (ย่อเส้นทุนก่อนส่ง ดูข้างล่าง) |
| `GET /api/audit` | `logs/audit.jsonl` (ส่งเฉพาะ 500 บรรทัดท้าย) |
| `GET /api/candles` | `data/candles/<ตลาด>/<symbol>/<tf>.csv` (ส่งเฉพาะแท่งท้ายสุด) |
| `GET /api/candles/available` | คลังแท่งเทียนมีอะไรอยู่บ้าง |
| `GET /api/kline` | แท่งเทียนจาก REST สาธารณะของ GRVT (ไม่ต้องมีคีย์) |
| `GET /api/market/{kind}` | สมุดคำสั่ง · ซื้อขายล่าสุด · ticker · funding · สเปคสัญญา (สาธารณะเหมือนกัน) |
| `GET /api/account/{kind}` | บัญชีจริงจาก GRVT — ต้องมีกุญแจที่เซิร์ฟเวอร์ อ่านอย่างเดียว |
| `GET /api/code` | **ซอร์สโค้ดจริงของบอท** อ่านจาก `BOARD_CODE` อ่านอย่างเดียว เฉพาะ `.py` |
| `GET /api/stages` | ห้าขั้นใช้ฟังก์ชันไหนบ้าง — ถามบอทก่อน (`logs/state.json`) ถ้าไม่มีค่อยอ่าน `BOARD_CONFIG` |
| `GET /api/runs` | `logs/runs.jsonl` — จับคู่บรรทัดเริ่มกับบรรทัดจบด้วย id |
| `GET /api/days` | สรุป `logs/audit.jsonl` **ทั้งไฟล์** เป็นรายวัน สำหรับปฏิทิน |
| `GET /api/health` | สำหรับ health check ของ Railway |

`/api/account/{kind}` รับเจ็ดชื่อ รับ `?limit=` เฉพาะชื่อที่เป็นประวัติ

| kind | ตอบว่าอะไร |
|---|---|
| `summary` | ทุนรวม · เงินที่ใช้ได้ · กำไรที่ยังไม่ปิด · หลักประกัน |
| `positions` | ไม้ที่ถืออยู่ตอนนี้ |
| `open_orders` | ใบที่ยังค้างบนสมุดคำสั่ง |
| `order_history` | ออเดอร์ที่ส่งไปแล้ว พร้อมสถานะ (รวมใบที่ถูกปฏิเสธ) |
| `fills` | ที่ได้ไม้จริง พร้อม **ค่าธรรมเนียมที่จ่ายจริง** |
| `funding` | ค่าถือข้ามคืนที่ถูกเก็บไปแล้ว |
| `closed` | ไม้ที่ปิดแล้ว: `realized_pnl` (ส่วนต่างราคา **ยังไม่หักค่าธรรมเนียม**) กับ `cumulative_fee` แยกกัน บอร์ดลบให้เหมือนหน้า GRVT |

`/api/candles` รับ `?exchange=&symbol=&interval=&limit=` (ค่าตั้งต้น grvt / BTC_USDT_Perp / 5m / 400)
ชื่อที่ไม่ใช่ชื่อไฟล์ธรรมดาถูกปฏิเสธทิ้ง ไม่ได้พยายามทำความสะอาดให้ — คำขอที่มี `..`
คือบั๊กหรือการโจมตี ทั้งสองอย่างไม่สมควรได้รับความพยายาม

ไฟล์ที่ยังไม่มีไม่ใช่ error — ตอบ `{"present": false, "reason": "..."}`
เพราะ "บอทยังไม่ได้รัน" กับ "บอร์ดพัง" เป็นคนละเรื่อง และหน้าจอต้องบอกให้ถูก

### `/api/code` ส่งทีละฟังก์ชัน

`?file=tradebot/risk.py&line=100` ตอบกลับเป็น **ฟังก์ชันที่ครอบบรรทัดนั้น** พร้อมเลขบรรทัดจริง
ไม่ส่งทั้งไฟล์ เพราะคำถามคือ "ตรงนี้ทำอะไร" ไม่ใช่ "ไฟล์นี้มีอะไรบ้าง"

- ชื่อไฟล์มาจากร่องรอยที่บอทเขียนเอง จึงเป็น path จาก root ของแพ็กเกจเสมอ
- **ปฏิเสธก่อนแตะดิสก์**: ชื่อที่มี `..` · ขึ้นต้นด้วย `/` · มี `\` หรือ `:` · ไม่ลงท้าย `.py`
  แล้วยัง canonicalize ซ้ำอีกชั้นเพื่อกัน symlink ที่ชี้ออกนอกโฟลเดอร์
- **ไม่แคช** คนเรียนแก้ไฟล์กลยุทธ์แล้วอยากเห็นการ์ดเปลี่ยนตาม แคชจะทำให้บอร์ดโกหก
  หลังแก้ครั้งแรกพอดี
- หาขอบฟังก์ชันด้วยย่อหน้าแบบ Python **แต่นับวงเล็บของ signature ก่อน** —
  `def risk_gate(` ที่พารามิเตอร์ยาวหลายบรรทัดจะจบด้วย `) -> Decision:` ที่ย่อหน้าเท่ากับ `def`
  ถ้าดูแต่ย่อหน้าจะตัดฟังก์ชันจบที่ signature ของตัวเอง

### `/api/runs` และ `/api/days` อ่านทั้งไฟล์ ไม่ใช่แค่หาง

การ์ดสดอ่าน audit แค่ 500 บรรทัดท้าย เพราะมันถามว่า "ตอนนี้เป็นยังไง"
ส่วนประวัติกับปฏิทินถามว่า "ที่ผ่านมาเป็นยังไง" — ปฏิทินที่ช่องเก่าว่างเพราะบอร์ดอ่านไม่ถึง
คือปฏิทินที่โกหกเรื่องอดีต ซึ่งเป็นสิ่งเดียวที่ปฏิทินมีไว้ทำ สองเส้นทางนี้จึงอ่านทั้งไฟล์
แล้วสรุปที่เซิร์ฟเวอร์ครั้งเดียว

- **รอบที่ไม่มีบรรทัดจบ = รอบที่ถูกฆ่า** ไม่ใช่บั๊กของตัวเขียน · การ์ดขึ้นว่า "ยังไม่จบ"
  ไม่ใช่ซ่อนทิ้ง เพราะ "หยุดเอง" กับ "เครื่องหาย" เป็นคนละเรื่อง
- **วันที่มาจากสตริงที่บอทเขียน** ไม่ได้แปลง timestamp เป็นวันที่เอง เพราะการแปลงต้องเลือก
  timezone และตัวเลือกเดียวที่ซื่อสัตย์คืออันที่อยู่ในสตริงอยู่แล้ว
- tick ที่อ่านบัญชีไม่ได้เขียนทุนเป็น `0` ถ้าปล่อยเข้าไปวันนั้นจะกลายเป็นวันที่ขาดทุนหมดพอร์ต
  จึงกรองออกก่อนคิดต้นวัน/ท้ายวัน
- วันที่ไม่มีใครวัด `change` เป็น `null` **ไม่ใช่ 0** — ช่องว่างกับวันที่เท่าทุนคนละเรื่อง

### `/api/stages` ตอบได้ตั้งแต่บอทยังไม่เคยรัน

ร่องรอยคือความจริง แต่มันมีก็ต่อเมื่อบอทรันไปแล้วอย่างน้อยหนึ่งรอบ ก่อนหน้านั้นการ์ดจะไม่มีอะไรโชว์
ซึ่ง "ไม่มีอะไรโชว์" คือหน้าตาของบอร์ดที่พัง เซิร์ฟเวอร์จึงอ่านคอนฟิกแล้วตอบว่าห้าขั้นนี้
*จะ* ใช้ฟังก์ชันไหน

**ลำดับความน่าเชื่อถือ มีสามชั้น** และเรียงแบบนี้ด้วยเหตุผลเดียว คือใกล้ความจริงแค่ไหน

1. **ร่องรอยในแถว audit ล่าสุด** — ฟังก์ชันที่ interpreter เดินผ่านจริงในรอบนั้น
2. **`strategy_module` / `broker_module` ใน `logs/state.json`** — บอทเขียนตอนเริ่มทำงานว่า
   ตัวเอง import อะไรมา (`type(self.strategy).__module__`) **ไม่ใช่การเดา** และไม่สนว่าใครสั่งรัน
   ด้วยคอนฟิกไฟล์ไหน
3. **คอนฟิกไฟล์** — สิ่งที่ตั้งใจไว้ ซึ่งอาจไม่ใช่สิ่งที่รันอยู่

ชั้นที่ 2 มีเพราะชั้นที่ 3 ผิดได้ง่ายมาก: บอร์ดเห็น `config/config.yaml` แต่คนรันบอทด้วย
`--config config/testnet.yaml` ซึ่งเป็นคนละกลยุทธ์ · **ถามบอทดีกว่าเดาแทนบอท**

- อ่านแค่สองค่า: `exchange` (ชั้นบนสุด) กับ `trading.strategy` — สแกนทีละบรรทัด ไม่ลาก YAML parser
  เข้ามาเพื่ออ่านสองสตริง
- ชื่อโมดูลที่มาจาก `state.json` **ถูกตรวจเหมือนชื่อไฟล์จากข้างนอกทุกอย่าง** (ต้องขึ้นต้น
  `tradebot.` ตัวอักษรธรรมดาเท่านั้น ห้ามมี `..`) เพราะมันมาจากไฟล์บนดิสก์แล้วกลายเป็น path
- ชื่อกลยุทธ์ไม่ได้ตรงกับชื่อไฟล์เสมอ (`random` อยู่ใน `random_strategy.py`) จึงลองสองสะกด
  แล้วถอยไป `strategies/base.py` ซึ่งซื่อสัตย์กับการที่มันเป็นการเดา
- ตอบเลขบรรทัดของ `def` มาด้วย การ์ดจะได้ใช้กุญแจเดียวกับที่ได้จากร่องรอย
- **มีร่องรอยเมื่อไหร่ ร่องรอยชนะทันที** เพราะมันคือสิ่งที่เกิดขึ้นจริง ส่วนคอนฟิกคือสิ่งที่ตั้งใจไว้
- มีเทสที่เปิดไฟล์จริงแล้วยืนยันว่าทุกคู่ (ไฟล์, ฟังก์ชัน) ที่ตอบไปมีอยู่จริง

### `/api/backtest` ย่อก่อนส่ง

`logs/backtest.json` มีจุดบนเส้นทุน **หนึ่งจุดต่อหนึ่งแท่ง** — ทดสอบ 400 วันบน 5m
คือ 115,198 จุด ไฟล์ **11 MB** ส่งทั้งก้อนให้เบราว์เซอร์ที่จะวาดการ์ดกว้าง 400 พิกเซล
ไม่มีประโยชน์กับใคร เซิร์ฟเวอร์จึงย่อให้ก่อนครั้งเดียว

**วิธีย่อ: เก็บจุดต่ำสุดกับสูงสุดของทุกช่วง** ไม่ใช่หยิบทุกจุดที่ n เพราะแบบนั้น
ก้นของ drawdown ที่เกิดระหว่างสองจุดจะหายไปทั้งก้อน แล้วเส้นบนจอจะเรียบกว่า
ที่บัญชีเคยเป็นจริง — กราฟหยาบได้ แต่กราฟที่เข้าข้างตัวเองไม่ได้

- ไม้ที่ปิดแล้วส่งแค่ 200 ไม้ล่าสุด และบอกจำนวนที่ไม่ได้ส่งมาด้วย
- `curve_total` / `curve_kept` ติดมากับคำตอบ เพราะ "600 จุด จาก 115,198"
  เป็นคำพูดที่ต่างจาก "600 จุด"
- **ตัวเลขยังเป็นสตริงเต็มหลักเหมือนในไฟล์** ที่นี่ไม่แปลงเงินเป็น number

## การ์ดฝั่งบอท (13 พ.ย. 2026)

บอร์ดเปิดมาที่โซน "ตลาด" ปุ่มบนหัวบอร์ดกระโดดไปอีกสองโซนได้ (`ตลาด` · `บอท` · `ทดสอบ`)
และ `พอดีจอ` ย่อให้เห็นทุกการ์ดในครั้งเดียว — แคนวาสไร้ขอบเขตมีประโยชน์ก็ต่อเมื่อ
กลับไปที่การ์ดได้ นักเรียนที่เลื่อนไปเจอที่ว่างคือนักเรียนที่หาบอร์ดไม่เจอแล้ว

โซน **บอท** — จาก `state.json` + `audit.jsonl`

| การ์ด | บอกอะไร |
|---|---|
| 1-5 (pipeline) | ห้าการ์ดเรียงกัน: ข้อมูลตลาด · กลยุทธ์ · ด่านความเสี่ยง · ส่งคำสั่ง · ไม้ที่ถืออยู่ · **แต่ละใบโชว์โค้ดจริงที่เพิ่งเดิน** |
| โค้ดที่เพิ่งเดิน | ฟังก์ชันเต็มๆ ของขั้นที่เลือก บรรทัดที่เดินจริงสว่าง บรรทัดที่ไม่ได้เดินยังอยู่ |
| ทุนกับสถานะบอท | ทุนตอนนี้ · กำไรขาดทุนวันนี้ · ต่ำกว่าพีคเท่าไร · ออเดอร์ที่ส่งแล้ว · **ถ้า halt ขึ้นบนสุด** |
| สิ่งที่บอทตัดสินใจ | เฉพาะจังหวะที่บอท*ทำอะไร* ใหม่สุดบน · tick ที่ดูแล้วเฉยๆ ไม่ขึ้น |

### เส้นเชื่อมกับจุดที่วิ่งบนเส้น

การ์ดทั้งห้าต่อกันด้วยเส้นโค้ง มีหัวลูกศรบอกทิศ และ **ทุนกับสถานะบอท → ด่านความเสี่ยง**
(เพราะเพดานขาดทุนรายวันเป็นเรื่องของเงิน ไม่ใช่ของตลาด) กับ **ส่งคำสั่ง → สิ่งที่บอทตัดสินใจ**

- **เส้นเทาประ = ต่อถึงกัน แต่ตอนนี้ไม่มีอะไรเดิน**
- **เส้นส้มมีจุดกลมวิ่ง = ข้อมูลกำลังเดินผ่านเส้นนั้นจริง** เงื่อนไขเดียวกับแดชบอร์ด Node เป๊ะ:
  ต้นทางทำงานเสร็จ (`Ok`) **และ** ปลายทางได้ทำอะไรกับมันแล้ว (ไม่ใช่ `Idle`)
  — ถูกด่านปฏิเสธก็นับว่าเดินไปถึง เพราะมันไปถึงจริง
- จุดวิ่งด้วยความเร็วคงที่ **85 พิกเซลต่อวินาที** ไม่ใช่ "หนึ่งรอบต่อวินาที" เส้นสั้นเส้นยาว
  จึงดูเป็นวัสดุเดียวกัน และจำนวนจุดคิดจากความยาวเส้น (1 จุดต่อ ~55 พิกเซล มากสุด 5)
- บอร์ดวาดถี่ขึ้นเป็น 30 เฟรม/วินาทีเฉพาะตอนมีเส้นวิ่ง ปกติ 10 เฟรม/วินาที

**ทำไมเส้นไม่สว่างตลอดเวลา:** บอร์ดที่ทุกเส้นเรืองแสงตลอดคือ screensaver
คนดูต้องแยกบอทที่ทำงานกับบอทที่ค้างได้ด้วยการชำเลืองมองครั้งเดียว นั่นคือหน้าที่ทั้งหมดของหน้าจอนี้

### กราฟตามตลาดทัน

สามอย่างที่ทำให้กราฟไม่ช้ากว่าหน้าเว็บของตลาด:

1. **แท่งเทียนถูกขอใหม่ทุก 10 วินาที** ไม่ใช่ขอครั้งเดียวตอนเปิด — เดิมพอแท่ง 5m
   ปิดไปแล้ว บอร์ดยังยืดแท่งเดิมด้วยราคาสดไปเรื่อยๆ สิบนาทีผ่านไปก็ยังเป็นแท่งเดิม
2. **stream ราคาขอถี่ที่สุดที่ตลาดให้: 200 ms** (เดิม 500) — ลองแล้ว 50/100/250
   ตลาดตอบ `Feed rate is invalid` (code 3030) ส่วน 200/500/1000 ผ่าน
3. **ราคาที่พับเข้าแท่งล่าสุดคือราคาซื้อขาย ไม่ใช่ mark** — แท่งเทียนมาจากชุด TRADE
   ส่วน mark เป็นดัชนีบวก basis สองค่านี้ห่างกันได้หลายสิบดอลลาร์ ถ้าเอา mark ไปพับ
   แท่งสุดท้ายจะมีขั้นที่ไม่มีใครเคยเทรดที่ราคานั้น (การ์ดราคายังโชว์ mark ตามเดิม
   เพราะมันเขียนกำกับไว้ว่า mark)

### เลือกคู่เทรดกับ timeframe บนหัวการ์ดกราฟ

ชิป `BTC ETH SOL XRP` กับ `1m 5m 15m 1h 4h 1d` อยู่บน**หัวการ์ดกราฟ** ไม่ใช่แถบบนสุด
— ปุ่มที่เปลี่ยนอะไรควรอยู่บนสิ่งที่มันเปลี่ยน แถบบนที่รวมทุกปุ่มของทั้งบอร์ดไว้
กลายเป็นแถวชิปที่ไม่บอกว่าแต่ละตัวทำอะไร แถบบนจึงเหลือแค่ปุ่มกระโดดโซนกับสถานะการเชื่อมต่อ

timeframe ยิงผ่าน `/api/kline` ทดสอบครบทุกค่าแล้ว · เปลี่ยน timeframe หรือคู่เทรดแล้ว
หน้าต่างซูมถูกรีเซ็ต เพราะ 120 แท่งของ 1m คือสองชั่วโมง แต่ของ 1d คือหนึ่งในสามปี

การ์ดใบไหนก็ใส่ปุ่มบนหัวตัวเองได้ด้วย `card::show_with_tools()` — ปุ่มถูกลงทะเบียน
**หลัง**ตัวจับการลากหัวการ์ด คลิกปุ่มจึงเป็นคลิกปุ่ม ไม่ใช่การเริ่มลากการ์ด

### กราฟซูมได้

ทั้งกราฟแท่งเทียนและเส้นทุน:

| ทำอะไร | ได้อะไร |
|---|---|
| ล้อเมาส์บนกราฟ | ซูมเข้า/ออก (ขอบขวาคือแท่งล่าสุดเสมอ) |
| ลากบนกราฟที่ซูมอยู่ | เลื่อนไปดูช่วงก่อนหน้า — **ไม่ใช่ลากบอร์ด** |
| ลากบนกราฟที่ยังไม่ซูม | เลื่อนบอร์ด เพราะกราฟที่เห็นครบทุกแท่งไม่มีอะไรให้เลื่อน |
| ดับเบิลคลิก | กลับไปดูทั้งชุด |

**ซูมหนึ่งคลิกล้อ = หนึ่งก้าว** egui เกลี่ย scroll หนึ่งคลิกออกไปหลายเฟรม ถ้าซูมเป็นก้าวคงที่
ทุกเฟรมที่ได้ค่า คลิกเดียวจะดิ่งไปจนสุด (เคยเป็นแบบนั้น เหลือ 15 แท่งจาก 400)
ตอนนี้ซูมเป็น**สัดส่วนของระยะ scroll** การแบ่งเป็นหลายเฟรมจึงคูณกลับได้เท่าเดิมพอดี

หัวการ์ดบอกเสมอว่ากำลังดูกี่แท่งจากทั้งหมดกี่แท่ง และ **เส้นประราคาสดจะหายไปเมื่อเลื่อนย้อนอดีต**
เพราะราคาวันนี้ไม่ได้อยู่บนแท่งของเมื่อวาน

ล้อเมาส์และการลากถูก "ยึด" ก่อนที่แคนวาสจะได้เห็น — egui เรียกตัวจัดการ pan/zoom ของ scene
**ก่อน**วาดการ์ด การ์ดจึงยึด input ของเฟรมตัวเองไม่ทัน บอร์ดเลยจำไว้ว่าเฟรมที่แล้วเมาส์อยู่บนกราฟไหน
(ช้าไปหนึ่งเฟรม ซึ่งมองไม่เห็น ส่วนบอร์ดที่เลื่อนหนีตอนกำลังซูมกราฟนั้นเห็นชัดมาก)
สำหรับการลาก บอร์ดบอก scene ให้ปล่อยปุ่มซ้ายเฉพาะเฟรมที่เมาส์อยู่บนกราฟที่ซูมอยู่
(`drag_pan_buttons`) ปุ่มกลางกับปุ่มขวายังลากบอร์ดได้เสมอ

โซน **ทดสอบ** — จาก `backtest.json`

| การ์ด | บอกอะไร |
|---|---|
| ผลการทดสอบย้อนหลัง | กำไรสุทธิ · % · CAGR · ค่าธรรมเนียม · **เทียบกับการอยู่เฉย** |
| ความเสี่ยงกับคุณภาพไม้ | drawdown · เวลาใต้พีค · เดือนแย่สุด · อัตราชนะ · expectancy R · sharpe · ด่านปฏิเสธอะไร |
| เส้นทุน | เส้นทุน + เส้นประทุนเริ่มต้น + **แรเงาทุกช่วงที่อยู่ใต้พีคเดิม** |
| อ่านก่อนเชื่อผลนี้ | คำเตือนของตัวรัน + ข้อจำกัดที่ต้องขึ้นจอทุกครั้ง ไม่ใช่เชิงอรรถ |

กฎที่การ์ดพวกนี้เล่นตาม เหมือน `../dashboard/lib/` เป๊ะ เพราะสองหน้าจอที่เถียงกันเรื่อง
บอทตัวเดียวแย่กว่ามีหน้าจอเดียว:

- **ค่าที่วัดไม่ได้พิมพ์ว่า "วัดไม่ได้" ไม่ใช่ 0.00** — "ไม่มี sharpe เพราะไม่มีผลตอบแทนให้วัด"
  กับ "sharpe เท่ากับศูนย์" เป็นคนละประโยค
- **เสมอ = การอยู่เฉยชนะ** เพราะการอยู่เฉยไม่เสียค่าธรรมเนียม ไม่กินเวลาเฝ้า และพังไม่ได้
- **ผลที่ยืนบนไม้ดีสุดสองไม้ถูกติดป้าย** ถ้าตัดสองไม้นั้นออกแล้วไม่เหลือกำไร
  การ์ดบอกตรงๆ ว่าผลนี้ยืนบนโชคสองครั้ง
- **ไม้น้อยกว่าเกณฑ์ของตัวบอทเอง** (`thin_sample_below`) ขึ้นเป็นข้อแรกของ "อ่านก่อนเชื่อผลนี้"
- ไฟล์ backtest ที่กำลังถูกเขียนใหม่ **ไม่ล้างผลเดิมที่อยู่บนจอ**

### โค้ดที่เดินจริง ไม่ใช่โค้ดที่น่าจะเดิน

การ์ดห้าใบเคยบอกแค่ *ผลลัพธ์* ของแต่ละขั้น ซึ่งตอบว่า "ตัดสินใจอะไร" แต่ไม่เคยตอบว่า
"มันทำงานอยู่ไหม" — คนที่นั่งดูบอทเงียบๆ แยกไม่ออกระหว่าง "กลยุทธ์ดูแล้วเลือกไม่เข้า"
กับ "ไม่มีอะไรรันอยู่เลย" ซึ่งเป็นคำถามที่การ์ดตอบได้แย่ที่สุด

ตอนนี้ **บอทจดเอง**: `tradebot/trace.py` ใช้ `sys.settrace` เก็บว่า interpreter เดินผ่าน
บรรทัดไหนบ้างในหนึ่ง tick แล้วเขียนลง `audit.jsonl` เป็นฟิลด์ `trace` บอร์ดเอาเลขบรรทัดนั้น
มาทาบกับไฟล์จริงที่ `/api/code` เปิดให้ — **ไม่ได้เดาจากผลลัพธ์** ว่าโค้ดน่าจะไปทางไหน

- การ์ดแต่ละใบโชว์ 5 บรรทัดแรกที่เดิน พอให้เห็นว่า "ขยับอยู่"
- การ์ด **โค้ดที่เพิ่งเดิน** กว้างพอให้อ่านทั้งฟังก์ชัน กดเลข 1-5 บนหัวการ์ดเพื่อสลับขั้น
- บรรทัดที่ไม่ได้เดิน**ยังอยู่แต่หรี่** เพราะกิ่งที่ *ไม่ได้* ไปคือครึ่งหนึ่งของสิ่งที่คนอ่านอยากรู้
- ลูปที่วนหลายรอบมีเลข `×n` ท้ายบรรทัด ซึ่งเป็นสิ่งเดียวที่โค้ดนิ่งๆ บอกไม่ได้
- รอบที่เพิ่งเดินสว่างกว่า แล้วค่อยๆ หรี่ลงใน 0.9 วินาที — บอทที่หยุดไปแล้วกับบอทที่ทำงานอยู่
  จะได้ไม่หน้าตาเหมือนกัน
- **หัวอ่านเดินทีละบรรทัดแล้ววนกลับ** ตามลำดับที่ interpreter เดินจริง (`trace.path`)
  ไม่ใช่แค่ระบายสีว่าบรรทัดไหนเคยเดิน · แปดบรรทัดต่อวินาที · ลูปที่วนกลับมาบรรทัดเดิม
  นับเป็นคนละก้าว เพราะนั่นคือสิ่งที่เกิดขึ้นจริง
- **ตำแหน่งหัวอ่านคำนวณจากนาฬิกา ไม่ได้เก็บไว้** การ์ดทั้งห้าใบจึงอยู่ที่วินาทีเดียวกัน
  ของ tick เดียวกันโดยไม่ต้องมีตัวนับห้าตัวให้ตรงกัน · ปุ่ม "หยุด/เดิน" คือการแช่ค่านาฬิกาที่ถาม
- การ์ดขั้นโชว์**หน้าต่างห้าบรรทัดที่เลื่อนตามหัวอ่าน** ไม่ใช่ห้าบรรทัดแรกค้างไว้
- **ยังไม่เคยรันบอทก็เห็นโค้ด** การ์ดเปิดไฟล์ที่คอนฟิกบอกไว้ (`/api/stages`) แล้วบอกว่า
  "นี่คือโค้ดที่ขั้นนี้ใช้ · รันบอทแล้วบรรทัดที่เดินจริงจะสว่างขึ้นมา" — โค้ดก็คือโค้ด
  แค่ยังไม่มีอะไรสว่างบนนั้น
- ถ้าแม้แต่คอนฟิกก็บอกไม่ได้ว่าใช้ไฟล์ไหน การ์ดบอกให้ไปตรวจ `BOARD_CODE` / `BOARD_CONFIG`
  ไม่ใช่เงียบไปเฉยๆ

ค่าใช้จ่ายของการจด: ~3 ms ต่อ tick บน paper broker (0.85 ms → 4.0 ms) ส่วนของจริง
มี network เป็นหลักร้อย ms ต่อ tick จึงกลบมิด · ปิดด้วย `--no-trace` ได้

## โซนประวัติ — รอบที่ผ่านมา และปฏิทินรายวัน

| การ์ด | บอกอะไร |
|---|---|
| ประวัติการรัน | ทุกรอบที่บอทเคยรัน ใหม่สุดบน · เริ่มกี่โมง นานเท่าไร กลยุทธ์ไหน ที่ไหน กี่ออเดอร์ ได้เสียเท่าไร |
| ปฏิทินรายวัน | หนึ่งเดือนเป็นช่องสี่เหลี่ยม เขียว/แดงตามผลของวัน · วันล่าสุดมีกรอบส้ม |

**ทำไมต้องมีสมุดรอบการรันแยก** — audit trail บอกว่าแต่ละ tick เกิดอะไร แต่ไม่บอกว่ารอบไหนจบ
รอบไหนเริ่ม การเดาจาก "ช่องว่างระหว่าง timestamp" ต้องรู้ loop interval ก่อน และต้องสมมติว่า
เครื่องไม่หลับและนาฬิกาไม่ขยับ · บอทจึงเขียนลง `logs/runs.jsonl` เอง: หนึ่งบรรทัดตอนเริ่ม
หนึ่งบรรทัดตอนจบ ใช้ id เดียวกัน

**สองบรรทัดไม่ใช่บรรทัดเดียวที่เขียนทับ** เพราะไฟล์นี้เขียนต่อท้ายอย่างเดียว และโปรเซสที่ถูกฆ่า
ไม่มีโอกาสเขียนบรรทัดที่สอง — รอบที่ไม่มีบรรทัดจบจึงเป็นข้อมูล ไม่ใช่ความผิดพลาด

ปฏิทินนับจากวันที่ในสตริงที่บอทเขียน ช่องที่บอทไม่ได้รันคือ**ช่องว่าง ไม่ใช่วันที่เท่าทุน**
และตัวเลขในช่องคือทุนท้ายวันลบทุนต้นวัน ซึ่ง**รวมกำไรที่ยังไม่ปิด** (ของจริงที่ realized แล้ว
อยู่ในการ์ด "ไม้ที่ปิดแล้ว" โซนบัญชี)

## เน็ตกระตุกแล้วบอร์ดทำอะไร

หน้าจอราคาที่ค้างโดยไม่บอกว่าค้าง คือความผิดพลาดที่แย่ที่สุดของจอแบบนี้ เพราะมันไม่มีอะไรดูผิดเลย
บอร์ดจึงมีสามชั้น:

**1. เฝ้าว่าสายยังมีชีวิตไหม** — ไม่ใช่แค่รอให้ซ็อกเก็ตบอกว่าปิด

| อาการ | บอร์ดทำอะไร |
|---|---|
| ไม่มีราคาเข้ามาเกิน 8 วินาที (ซ็อกเก็ตยัง "เปิด" อยู่) | ทิ้งแล้วต่อใหม่ |
| ต่อไม่ติดภายใน 12 วินาที | ทิ้งแล้วต่อใหม่ |
| ซ็อกเก็ต error หรือถูกปิด | ทิ้งแล้วต่อใหม่ (เดิม error ทำให้ค้างถาวร) |

รอก่อนลองใหม่แบบถอยหลัง 2 → 4 → 8 → 16 → 30 วินาที และ**รีเซ็ตเป็น 2 ทันทีที่ได้ราคาจริง**
กันทั้งการถล่มตลาดตอนเน็ตหาย และการรอสิบนาทีตอนเน็ตกลับมา

**2. คำขอที่หายกลางทางไม่แช่แข็งการ์ด** — ทุกการดึงข้อมูลมีกฎ "ทีละคำขอ" เพื่อไม่ให้ยิงรัว
ถ้าคำตอบไม่เคยกลับมา กฎนั้นจะค้างตลอด session · ตอนนี้เกิน 20 วินาทีถือว่าหาย แล้วถามใหม่

**3. จอบอกเสมอว่าข้อมูลหยุดเมื่อไร**

- แถบบนขวา: `ต่ออยู่` → `เงียบ N วิ` → `หลุด · ต่อใหม่ใน N วิ`
- การ์ดราคาเขียนใต้ราคาเลยว่า `ราคาค้างมา N วินาที`
- การ์ดที่ยังโชว์ข้อมูลเก่าอยู่เพราะดึงใหม่ไม่สำเร็จ ติดป้ายแดง **`ข้อมูลค้าง`**
- **กราฟเลิกพับราคาสดที่ค้างเข้าแท่งล่าสุด** — แท่งเทียนยังมาทาง HTTP ทุก 10 วินาที
  สายที่ตายจึงทำให้เสียแค่การเคลื่อนไหวไม่กี่วินาทีสุดท้าย ไม่ใช่ทั้งกราฟ

ทดสอบของจริงแล้วทั้งสองทาง: บีบ watchdog ให้ไวแล้วดูวงจร ทิ้ง → ต่อใหม่ → subscribe → ได้ราคา
ครบรอบ · และฆ่า `board-server` ทิ้งกลางคัน การ์ดขึ้น `ข้อมูลค้าง` ทุกใบ พอเปิดเซิร์ฟเวอร์กลับมา
ทุกการ์ดกลับมาเองโดยไม่ต้องปิดแอป

## โซนตลาด: ข้อมูลชุดเดียวกับหน้าเทรดของ GRVT

ทุกอย่างในโซนนี้มาจาก endpoint **สาธารณะ** ของ GRVT ผ่าน `/api/market/{kind}`
(`book` `trade` `ticker` `funding` `instrument`) — ไม่ต้องมีคีย์ อ่านอย่างเดียว

| การ์ด | ตรงกับอะไรบนเว็บ GRVT |
|---|---|
| ราคาตลาด | แถบบนสุด: mark · ราคาล่าสุด · เปลี่ยนแปลง % · 24h สูง/ต่ำ · ปริมาณ · สัญญาคงค้าง |
| สมุดคำสั่งซื้อขาย | แท็บ Order book: ราคา / จำนวน / **สะสม** พร้อมแถบความลึก · บรรทัดส่วนต่าง · **แถบแรงซื้อ/แรงขาย** |
| ซื้อขายล่าสุด | แท็บ Trades: เวลา · ราคา · จำนวน |
| ความลึกของตลาด | แท็บ Depth: บันไดสะสมสองฝั่ง |
| ค่าถือข้ามคืน (funding) | แท็บ Funding: อัตรา 8 ชม. · คิดเป็นต่อปี · ใครจ่ายใคร · นับถอยหลังรอบถัดไป · ประวัติ |
| สเปคสัญญากับสถิติ 24 ชม. | แท็บ Info: tick size · ขนาดขั้นต่ำ · มูลค่าขั้นต่ำ · ถือได้มากสุด · เพดาน funding |

รายละเอียดที่ตั้งใจให้ตรงกับของจริง:

- **อัตรา funding ที่ตลาดส่งมาเป็นเปอร์เซ็นต์อยู่แล้ว** `0.01` คือ `+0.0100%` ไม่ใช่ 1%
  หน้าเว็บของ GRVT แสดง `+0.0100% / +10.9500%` และบอร์ดคำนวณต่อปีด้วยสูตรเดียวกัน
  (อัตรา × 24/ช่วงชั่วโมง × 365) ได้ `+10.95%` ตรงกัน
- **นับถอยหลังรอบ funding ใช้นาฬิกาของตลาด** ไม่ใช่นาฬิกาเครื่อง: `event_time` กับ
  `next_funding_time` มาจากคำตอบเดียวกัน เครื่องที่ตั้งเวลาเพี้ยนจึงไม่ทำให้นับผิด
- **แถบในสมุดคำสั่งคือยอดสะสม** ไม่ใช่ขนาดของชั้นนั้นชั้นเดียว และสองฝั่งใช้สเกลเดียวกัน
  ไม่งั้นฝั่งที่บางจะดูลึกเท่าฝั่งที่หนา
- **แถบแรงซื้อ/แรงขายใต้สมุด คิดจากทั้งกระดาน** ไม่ใช่เฉพาะชั้นที่เห็นบนจอ เพราะนั่นคือ
  สิ่งที่หน้าจอของตลาดหมายถึง — วัดเทียบกันเมื่อ 13 พ.ย. 2026: เว็บขึ้น `Buy 55% / 45% Sell`
  ทั้งกระดานได้ 55.1% ส่วนเก้าชั้นที่เห็นได้ 65% (ตอนแรกบอร์ดคิดจากชั้นที่เห็น เลยไม่ตรง)
  ฝั่ง bid ของ testnet มักมีไม้ก้อนใหญ่ตั้งห่างจากกระดานหลายสิบดอลลาร์ ซึ่งตลาดนับด้วย
  จึงดึงสมุดมา `depth=500` (ได้ครบทั้งกระดาน ~120 ชั้น ไม่กี่กิโลไบต์)
- **สีในแถวซื้อขายอยู่ที่ราคา** เขียว = ฝั่งซื้อเป็นคนข้ามสเปรด ไม่ได้แปลว่าราคาขึ้น
- **กราฟความลึกตัดเฉพาะ ±1.5% รอบกลางราคา** และเขียนไว้บนหัวการ์ด เพราะสมุด 50 ชั้น
  บนตลาดเงียบมีออเดอร์ไกลถึง +50% ถ้าสเกลตามนั้นส่วนที่สำคัญจะแบนติดแกน
- **คำตอบที่เป็นของเหรียญอื่นถูกทิ้ง** ตอนสลับเหรียญมีคำขอค้างอยู่ในอากาศเสมอ
  สมุดของ BTC ใต้หัวข้อ SOL คือคำโกหกแบบเดียวกับที่ feed เคยทำ

**ความถี่ที่ถาม:** สมุด 1 วินาที · ซื้อขาย 1.5 วินาที · ticker 2 วินาที · funding 60 วินาที
· สเปคสัญญา 5 นาที — ถ้าเปิดบอร์ดพร้อมกันทั้งห้องจากคนละเครื่อง แต่ละเครื่องถามเอง
(เซิร์ฟเวอร์ยังไม่มี cache ร่วม ถ้าจะใช้แบบนั้นควรใส่)

## โหมดควบคุม และ TradeBot.exe (ดับเบิลคลิกแล้วใช้ได้เลย)

ข้อยกเว้นข้อเดียวของ "บอร์ดอ่านอย่างเดียว": บนเครื่องของนักเรียนเอง บอร์ดสั่ง**เริ่ม/หยุดบอท**ได้
(`server/src/control.rs`) เพื่อให้ไม่ต้องเปิดเทอร์มินัล เซิร์ฟเวอร์เองยังไม่เคยเซ็นหรือส่งออเดอร์
มันแค่รันโปรแกรม `tradebot` ที่นักเรียนมีอยู่แล้ว และเปิดได้ก็ต่อเมื่อ**ทั้งสองข้อ**นี้จริง

- ตั้ง `BOARD_CONTROL=1` (หรือเปิดผ่าน `TradeBot.exe` ซึ่งเปิดให้เอง)
- ผูกกับ loopback (`127.0.0.1`) ถ้าผูก `0.0.0.0` อย่างบน Railway เส้นทางเหล่านี้**ไม่ถูกลงทะเบียนเลย** (404)

`BOARD_BOT_ROOT` = โฟลเดอร์บอท (ที่รัน `.venv\Scripts\tradebot.exe` และเก็บ `config\.env`, `logs\`)
ตอนพัฒนา: `.\start.ps1 -Control` ตั้งทั้งสามตัวแปร (`BOARD_CONTROL` `BOARD_BIND=127.0.0.1` `BOARD_BOT_ROOT`) ให้

| เส้นทาง | ทำอะไร |
|---|---|
| `GET  /api/control` | สถานะ: `setup` (ready/installing/failed/missing) · `job` · `output` 300 บรรทัดท้าย · `keys` (true/false ไม่มีค่า) · `halted` (paper/testnet) |
| `POST /api/control/run` `{"mode":"paper"\|"testnet"}` | paper: `--config config/demo.yaml --dry-run --paper-live --close-at-end` · testnet: `--config config/testnet.yaml --live --close-at-end` |
| `POST /api/control/stop` | เขียน `logs/stop.request` ให้บอทจบเอง (แล้ว `--close-at-end` ปิดไม้) · ครบ 90 วินาทียังไม่จบค่อยบังคับปิด |
| `POST /api/control/check` | `--config config/testnet.yaml --check` · ถ้า `config/.env` มี API key + private key + เลขบัญชีครบ จะดึงแท่งเทียนจริงก่อน (`--live --fetch-candles --days 2`) แล้วค่อยตรวจ ทั้งสองขั้นเป็นงานเดียว (`job.action` = `check`, `exit_code` = ของด่านตรวจ) · ถ้ากุญแจไม่ครบ ข้ามการดึงแล้วบอกในบรรทัดแรกของ `output` |
| `POST /api/control/resume` `{"mode"}` | ปลดสถานะ halt ของ paper หรือ testnet |
| `POST /api/control/keys` | รวมค่าเข้า `config/.env` (ค่าที่ว่างหรือไม่ส่ง = ไม่แตะ) แล้วการ์ดบัญชีใช้กุญแจใหม่ทันที ไม่ต้องรีสตาร์ท |

ทุก POST ต้องมี header `x-board-control: 1` และ `Host` ต้องเป็น `127.0.0.1`/`localhost`/`[::1]`
ถ้ามี `Origin` ต้องเท่ากับ `Host` — ไม่งั้น 403 (กันเว็บอื่นในเบราว์เซอร์เดียวกันมาสั่งบอท รวมถึง DNS rebinding)
สั่งซ้อนไม่ได้ (409) และกุญแจ**ไม่เคยถูกส่งออกจากเซิร์ฟเวอร์ ไม่เคยลง log** — บรรทัด output ที่บังเอิญมีค่ากุญแจจะถูกแทนด้วย `***`

`TradeBot.exe` = เซิร์ฟเวอร์ตัวเดียวกันนี้ เปิดโหมดควบคุมให้ ผูก `127.0.0.1:4340` และเปิดเบราว์เซอร์ที่ `#control`
โฟลเดอร์บอทคือโฟลเดอร์ที่ exe วางอยู่ (ตัวเลือก `--root <โฟลเดอร์>` สำหรับตอนพัฒนา) ถ้ายังไม่มี `.venv`
มันสร้างให้เองด้วย `uv` (`board-pack\uv.exe` ที่ `pack.ps1` โหลดมา ปักเวอร์ชัน + ตรวจ SHA-256)
ปิดหน้าต่าง = สั่งบอทหยุดอย่างสุภาพก่อน และมี Windows job object (`KILL_ON_JOB_CLOSE`) เป็นด่านสุดท้าย
เพื่อไม่ให้บอทค้างอยู่หลังหน้าต่างหาย

## ขึ้น Railway

```bash
docker build -t tradebot-board .
```

Railway อ่าน `Dockerfile` เองและตั้ง `PORT` ให้ เซิร์ฟเวอร์อ่านค่านั้นอยู่แล้ว
บน Railway จะไม่มีโฟลเดอร์ logs ให้ mount — บอร์ดยังเปิดได้และแสดงตลาดสด
เพราะ stream ตลาดวิ่งในเบราว์เซอร์ของคนดู ไม่ได้วิ่งผ่านเซิร์ฟเวอร์

| ตัวแปร | ค่าตั้งต้น | ใช้ทำอะไร |
|---|---|---|
| `PORT` | 4340 | Railway ตั้งให้เอง |
| `BOARD_DIST` | `dist` | โฟลเดอร์ WASM ที่ trunk สร้าง |
| `BOARD_LOGS` | `logs` | โฟลเดอร์ log ของบอท |
| `BOARD_CANDLES` | `data/candles` | คลังแท่งเทียนที่บอทโหลดไว้ |
| `BOARD_GRVT_ENV` | `testnet` | `testnet` หรือ `prod` — ใช้เลือกว่า kline มาจากที่ไหน |

## หน้าตา

ขอบบางระดับเส้นผม ตัวเลขเป็น monospace

**ส้มแปลว่า "ระบบ" ไม่เคยแปลว่า "เงิน"** — แท็บที่เลือก เครื่องมือที่ถือ
ส่วนกำไรขาดทุนใช้เขียว/เหลือง/แดงคนละชุด ถ้าปนกัน สีที่แปลว่า "กำลังเลือกอยู่"
จะไปอยู่ข้างสีที่แปลว่า "ขาดทุน" ซึ่งเป็นความสับสนเดียวที่หน้าจอเทรดรับไม่ได้

## แท่งเทียนมาจากไหน

การ์ดกราฟลองสองที่ ตามลำดับ และ**บอกบนหัวการ์ดเสมอว่าใช้อันไหนอยู่**

1. **คลังบอท** — `data/candles/...` ที่บอทโหลดไว้ด้วย `--fetch-candles`
   คือสิ่งที่**บอทมองเห็น**ตอนตัดสินใจ ใช้เมื่ออยากรู้ว่าทำไมบอทถึงเทรดแบบนั้น
2. **ตลาดสด** — `POST market-data.<env>.grvt.io/full/v1/kline` ผ่าน `/api/kline`
   **ไม่ต้องมีคีย์** ใช้เมื่ออยากดูตลาดจริง

**ถ้าคลังของบอทว่าง บอร์ดจะถอยไปใช้ตลาดสดให้เอง** — นักเรียนที่ยังไม่มี API key
เปิดมาก็เห็นกราฟจริงทันที ไม่ต้องแก้ปัญหา credential กันทั้งห้องก่อน

timeframe ที่ `/api/kline` รับ: 1m 3m 5m 15m 30m 1h 2h 4h 8h 1d
ชื่ออื่นถูกปฏิเสธพร้อมบอกว่ามีอะไรให้ใช้บ้าง ไม่ส่งต่อไปให้ตลาดตอบ error ที่อ่านไม่ออก

## กราฟแท่งเทียน

การ์ด "ราคาสด" วาดแท่งเทียนจากคลังของบอท แล้วเอาราคาสดจาก GRVT
**พับเข้าไปในแท่งล่าสุดที่ยังไม่ปิด** (close ขยับ · high/low ถูกดันตาม)
ถ้าไม่ทำแบบนี้ ขอบขวาของกราฟจะนิ่งทั้งที่ตลาดวิ่ง ซึ่งเป็นสิ่งเดียวที่กราฟสดห้ามทำ

- แกนราคาอยู่ขวา มีเส้นไกด์ 4 เส้น ทศนิยมปรับตามช่วงราคา
- ป้ายราคาล่าสุดสีตามทิศของแท่ง · ป้ายราคาสดสีครีม เพราะ**ราคาไม่ใช่กำไรขาดทุน**
- แท่งที่ยังไม่ปิดสีจางกว่าแท่งที่ปิดแล้ว
- ยังไม่มีแท่งในคลัง → การ์ดบอกเหตุผลพร้อมคำสั่งที่ต้องรัน แล้ววาดเส้นจากราคาสดไปก่อน

```bash
tradebot --fetch-candles --days 90    # แท่งไปอยู่ที่ data/candles/...
```

## ข้อจำกัดตอนนี้ (13 พ.ย. 2026)

- timeframe ยังตรึงที่ 5m ในหน้าจอ (route รับค่าอื่นได้แล้ว)
- ยังไม่มีปุ่มสลับแหล่งแท่งเทียนด้วยมือ — ตอนนี้เลือกให้อัตโนมัติอย่างเดียว
- ซูมด้วยล้อเมาส์ผ่านเทสแบบ headless แล้ว แต่ยังไม่ได้ลองด้วยเมาส์จริงบนเครื่องที่เขียน
  (สคริปต์อัตโนมัติส่ง event เมาส์เข้าหน้าต่างไม่ได้)
- ตำแหน่งการ์ดที่ลากแล้วยังไม่ถูกจำข้ามการเปิดใหม่ (แดชบอร์ด Node จำให้)
- การ์ด "ไม้ที่ปิดแล้ว" ของแท็บ backtest ฝั่งแดชบอร์ด ยังไม่มีคู่บนบอร์ดนี้
  (ข้อมูลส่งมาถึงแล้ว 200 ไม้ล่าสุด ยังไม่ได้ต่อเข้าการ์ด)
- สมุดคำสั่งมาจาก REST ที่ถามทุก 1 วินาที ไม่ใช่ stream — เห็นทุกชั้นจริง แต่ไม่ใช่ทุกการเปลี่ยนแปลง
- ยังไม่มี cache ฝั่งเซิร์ฟเวอร์ ถ้าหลายคนเปิดผ่านเซิร์ฟเวอร์ตัวเดียวจะยิงซ้ำกัน
- ยังไม่มี stream ส่วนตัว จึงยังไม่เห็น position/order ของบัญชีตัวเอง
- **ยังไม่เคย deploy ขึ้น Railway จริง** มีแต่ Dockerfile ที่ build ผ่านในเครื่อง
